# PRD 시공 현황

## 현장 요약 그래픽 (2026-09-29)

- 승인된 계정으로 조회한 남측 PRD 기록에서 전체 시공 완료율, 천공 기록 수, 시공 완료 수, 잔여 공수, 자재 반입 기록 수를 집계한다. 잔여는 타설일 미입력 공수이며 공정표 대비 지연 판단이 아니다.
- 공구별 완료율 그래프를 클릭하면 기존 공구 도면과 상세표로 이동한다. 요약은 남측 전체 기준이며 도면 검색·선택으로 분모가 바뀌지 않는다. 기록이 바뀌거나 날짜가 바뀔 때 요약을 갱신하고, 공 클릭·확대·이동만 할 때는 다시 그리지 않는다.
- 최근 8주 천공·시공 완료 실적은 한국 날짜 기준 월요일~일요일로 집계한다. 오늘 이후 날짜는 주간 실적에 포함하지 않으며, 전체 누적 수량은 기존 현황표처럼 날짜 입력 여부를 기준으로 한다. 그래프 아래에서 동일한 수치를 표로 확인할 수 있다.
- 요약 패널은 접을 수 있고 도면 전체 화면에서는 숨긴다. 로그아웃 시 요약 내용도 비운다. 북측·다른 공종에는 실제 기록이 없으므로 임의의 수치나 그래프를 표시하지 않는다.

서리풀 : 남측 > PRD는 승인된 Google 계정으로 로그인한 후 Supabase에서 고정 도면과 시공 기록을 불러온다. 파일 선택 및 도면 교체 UI는 제공하지 않는다. 원본 DXF를 수정하지 않고 원/문자/구역 정보만 추출한다.

로그인 설정, 권한, 서버 저장 및 이전 도면의 공개 이력은 [서리풀 로그인 문서](seoripul-login.md)를 참고한다. 초기 공개 배포와 달리 현재 도면 JSON은 정적 호스팅에서 제외한다.

## 지원 범위

- mm 단위 모형 공간의 CIRCLE과 TEXT. 블록/MTEXT/다른 단위는 현재 지원하지 않는다. INSERT가 남으면 경고한다.
- 번호 `-col_number`, 부재명 `-col_name`, 타입 `-col_type`, 반력 `-col_reaction` 레이어. TEXT의 정렬에 따라 삽입점 또는 정렬점을 사용한다.
- `-perimeter`, `-zoning`의 LWPOLYLINE. 닫힘 플래그 또는 일치하는 양 끝점으로 폐합을 판별한다. 곡선은 직선으로 표시하고 경고한다.
- 큰 원본 좌표는 평행이동만 하며 mm 크기를 유지한다. 원 지름과 레이어의 명시 공경은 데이터에서 구분한다. 공별 정보 화면에는 공 직경을 표시한다. 자재 엑셀로 공경을 확인·정정할 수 있으며 원본의 원 표시는 도면 기호로 유지한다.
- 문자는 가장 가까운 공과 연결한다. 최대 허용거리 밖은 미연결, 거리비가 애매하면 경고한다. 다중 번호/중복 번호/미연결 번호/다중 부재명은 확인 필요로 표시하고 강제로 재배정하지 않는다.

## 기록 및 저장

- 같은 도면 안에서는 DXF 객체 handle로 기록한다. 공 번호가 중복되어도 기록은 섞이지 않는다.
- 기본 도면의 ID는 원본 파일 SHA-256으로 유지한다. 이전 버전의 같은 DXF 기록을 명시적으로 가져올 수 있다. 저장 도면 형상은 사용하지 않고 고정된 기본 도면과 기존 기록을 결합한다.
- 천공 일자, 자재 반입 일자, 타설일(완료일), 메모. 저장 버튼과 다른 공 선택 시 저장한다. 미저장 변경은 창 닫기 전 경고한다.
- 자재 반입이 천공보다 먼저일 수 있다. 타설일(완료일)이 입력된 선행 작업 일자보다 빠르면 저장하지 않는다. 비어 있는 날짜는 추정하지 않는다.
- 상태는 미착수/천공 완료/자재 반입/천공·반입 완료/시공 완료. 타설일(완료일)이 있으면 시공 완료로 표시한다.
- 날짜·메모는 서버에 저장한다. 다른 사용자 변경은 주기적 조회 또는 최신 기록 버튼으로 불러온다. 같은 공의 동시 변경은 버전 충돌로 알리고 입력을 보존한다. 서버 오류 시 저장된 것으로 표시하지 않는다.
- 상단 백업·복원·CSV 메뉴는 사용자 요청으로 제거했다. 기존 브라우저 기록은 같은 도면 ID를 확인해 사용자가 가져오기 버튼으로 이전한다.

## 확인

`node --test tests/prd.test.cjs tests/rc-beam-ui.test.cjs tests/report-print.test.cjs`

실제 제공 도면 로컬 검증: 공 790개, 구역/외곽선 11개, 확인 필요 9공. 기본 데이터에는 사용자 시공 기록을 넣지 않는다. 원본 절대좌표 원점도 포함하지 않는다.

## 공구별 상세 현황

- ZONING 경계 10개: A1·A2·A3 / B1·B2·B3 / C1·C2·C3·C4. 사용자 확인에 따라 B4는 생성하지 않는다.
- 고정 도면의 구역선에 공구 이름을 붙이며, 공 번호 문자열이 아닌 공 중심의 다각형 포함 여부로 소속을 판정한다. 현재 790공 모두 하나의 공구에 포함된다.
- 경계 중복 또는 경계 밖 공은 미분류로 표시하며 복수 공구에 중복 합산하지 않는다.
- 공구 영역·이름 또는 공구 버튼 클릭으로 해당 공구를 선택한다. 다른 공구는 흐리게 표시하고, 전체 버튼으로 해제한다. 기존 개별 공 클릭과 지도 이동/확대 기능은 유지한다.
- 오른쪽에 공구 요약, 도면 아래에 공구별 상세 수량과 공별 날짜·메모 목록을 표시한다. 목록의 공 번호로 해당 공을 선택·확대할 수 있다.
- 천공·자재 반입·타설 누적 수량은 각각 날짜가 있는 공 수다. 상태별 5개 수량은 서로 배타적이다. 시공률은 타설일(완료일) 입력 공 수 / 해당 공구 전체 공 수로 계산한다. 검색·상태 필터는 표시 목록만 바꾸고 공구 시공률 분모를 바꾸지 않는다.
- 날짜 저장·삭제 후 현황을 다시 계산한다. 기존 저장 키와 도면 SHA-256 ID를 유지하므로 기존 시공 기록이 이어진다.
- 검사: `node --test tests/prd-zones.test.cjs tests/prd.test.cjs tests/rc-beam-ui.test.cjs tests/report-print.test.cjs`

## 화면 정리 및 전체 화면

- 상단 제목·파일 정보·백업/복원/CSV 메뉴와 고정 안내를 삭제했다. 기존 localStorage 원본은 가져오기 이후에도 보존한다.
- 공별 정보는 공구·부재명·타입·공경 레이어만 표시한다. 객체 번호·반력 원문·도면 원 지름은 데이터에서 삭제하지 않고 표시에서 제외한다.
- 도면 아래 중복 공 번호 버튼 목록은 제거했다. 공구 상세 현황표의 날짜·메모 목록은 유지한다.
- 도면 도구줄의 전체 화면 버튼으로 확대한다. 브라우저 전체 화면이 지원되지 않으면 화면 전체를 채우는 레이아웃으로 대체한다.
- 전체 화면 진입 시 도면이 전체 폭을 차지한다. 공·공구 선택 시 오른쪽 상세 정보를 열며, 상세정보 열기/닫기로 표시를 바꿀 수 있다. 상세 목록 보기는 전체 화면을 종료하고 현황표로 이동한다.
- Esc, 닫기 버튼, 브라우저 전체 화면 종료로 복귀한다. 선택·날짜 입력·줌·이동 상태는 유지한다. 오류는 오류 영역, 저장/입력 상태는 공별 폼에 표시한다.

## 도면 조작 성능

- 같은 공구에서 공만 선택할 때는 이전/새 선택 원과 입력 폼만 갱신한다. 790개 원의 상태와 상세 현황표를 다시 만들지 않는다. 입력 중이던 기록은 기존처럼 먼저 저장하며, 저장 실패 시 선택을 유지한다.
- 번호 정렬과 검색용 문자열은 도면을 불러올 때 준비한다. 공구·필터·기록이 바뀔 때만 현황을 다시 계산하고, 원 속성은 값이 달라진 경우에만 쓴다.
- 이동·휠 확대 요청은 requestAnimationFrame으로 모아 한 프레임에 한 번 SVG viewBox를 갱신한다. 이동 시작 때 좌표 변환을 읽고, 이후에는 시작 위치와 총 이동량으로 계산한다. 이동 중에는 공구 글자 크기를 다시 쓰지 않는다.
- `node --test tests/prd-ui.test.cjs`로 선택 시 두 원만 갱신하는지, 현황표를 보존하는지, 공구/검색/자동 저장/저장 실패 및 이동·휠 연속 이벤트를 확인한다. DOM 어댑터 검사이며 실제 브라우저의 프레임 시간 측정을 대신하지 않는다.
- 브라우저에서 공구·공 선택, 드래그, 버튼·휠 확대, 날짜 저장, 전체 화면을 별도로 확인한다. 기본 도면 ID와 공 기록 키는 유지한다. 저장 위치만 서버로 이전한다.

## 남측·북측 메뉴 (2026-09-29)

- 대메뉴와 메인 목록을 `서리풀 : 남측`, `서리풀 : 북측` 순서로 표시하며 각각 PRD·철골보·슬래브·커튼월을 같은 순서로 제공한다. 커튼월은 시공 현황 기능 준비 안내 페이지다.
- 기존 도면과 시공 기록은 남측에서 그대로 사용한다. 북측은 도면 등록 전까지 준비 안내만 표시하며 남측 도면을 복제하거나 연결하지 않는다.
- 두 현장의 8개 페이지 모두 기존 Google 로그인 및 관리자 승인 정책을 공유한다. 북측에서 로그인하면 선택했던 북측 페이지로 돌아온다. 북측 전용 승인 그룹은 이번 변경에 포함하지 않는다.
- 북측 실제 도면을 연결할 때는 별도 도면 ID와 서버 접근 제어를 적용해야 한다. 현재 북측 페이지에는 비공개 현장 데이터가 포함되지 않는다.


### 전체화면 그래프와 도면 전환 (2026-09-30)

전체화면 도구 모음의 `현황 그래프`로 기존 요약 그래프·주간 실적표를 열고, `도면으로 돌아가기`로 직전 확대 위치를 유지한 도면으로 복귀한다. 공구 탭과 `전체 도면`은 그래프 화면에서도 유지되며, 탭 또는 공구별 그래프를 선택하면 전체화면을 유지한 채 해당 도면 범위로 전환한다. 공구 전환 시 검색/상태 필터를 초기화하고 상세 입력 패널은 닫는다. 공을 선택하면 기존 상세 입력이 열린다.

동일한 대시보드 DOM을 이동해 사용하므로 서버 기록과 권한 흐름은 바뀌지 않는다. 전체화면 종료 시 원래 대시보드 위치와 접힘 상태를 복원하며, 로그아웃 시 전체화면과 그래프를 종료하고 기록을 비운다.


### 현장 통합 페이지 (2026-09-30)

남측(`site-prd`)·북측(`site-north-prd`) 각각 하나의 인증된 시공 현황 페이지에 PRD / 철골보 / 슬래브 / 커튼월 패널을 둔다. 메뉴·홈 진입점도 현장별 `시공 현황` 하나로 통합한다. 공종 드롭다운과 전체화면 버튼은 공통 헤더에 있으며, 전체화면을 종료하지 않고 공종을 전환한다. 북측과 미등록 공종은 준비 중 화면만 제공한다.

`site-workspace.js`는 공종 전환·전체화면·포커스 복원·권한 해제 시 전체화면 종료를 담당한다. 남측 PRD에서 다른 공종으로 이동할 때 미저장 입력을 먼저 서버에 저장하며 실패 시 PRD에 머물러 입력을 보존한다. PRD 도면의 선택 공구·확대 위치·현황 그래프 상태는 공종을 돌아와도 유지한다. 공 번호 검색은 제거하고 공구 선택과 시공 상태 필터는 유지한다. 모든 패널은 기존 `.site-content` 인증 게이트 안에 유지되며 서버 권한과 데이터 구조는 바꾸지 않는다.

### 엑셀 다운로드 (2026-09-30)

공통 헤더의 `엑셀 다운로드`는 남측 PRD의 현재 공구·상태 필터에 해당하는 저장 기록을 `.xlsx`로 내보낸다. 전체 자료는 `전체 도면`과 `전체 상태`를 선택한 후 내려받는다. 공구별 집계 / 공별 기록 / 최근 8주 실적 시트에 같은 범위를 적용하고 기준일·선택 범위·공수를 표시한다. 미입력 날짜는 빈 셀로 유지하며 날짜는 Excel 날짜 형식, 메모는 수식이 아닌 문자열로 쓴다. 다운로드 파일은 저장 시점의 실적 스냅샷이다.

미저장 입력은 다운로드 전에 저장하고 실패하면 생성을 중단한다. 생성 중 공종 전환은 막으며, 권한/계정이 변경되면 파일 다운로드를 취소한다. 북측 및 미등록 공종은 다운로드 버튼을 비활성화한다. 서버 업로드나 새로운 API 없이 브라우저 안에서 생성한다.

### 도면 도구 정리·범례·일반 사용자 입력

철골보·슬래브 도면 도구를 이동/보기 버튼 줄과 표시 옵션 줄로 정돈했다. 버튼과 선택 상자는 36 px 높이를 쓰고 체크박스와 이름은 가로로 정렬한다. 최신 기록은 PRD·철골보·슬래브 모두 공종 선택과 같은 최상단 메뉴에서 제공한다. 공종별 갱신 도구는 해당 공종에서만 표시한다.

철골보 상태 범례는 Canvas 외곽의 위치 지정 컨테이너 안에서 우측 상단에 고정한다. 도면 확대·이동의 영향을 받지 않으며 클릭을 가로채지 않는다. 그래프를 표시할 때는 도면과 범례를 함께 숨긴다.

승인된 일반 사용자(`viewer`)도 철골보·슬래브의 번호/이름·규격·완료일·메모 및 철골보 자재 반입일을 수정한다. 브라우저의 `canEditTrade`와 서버의 비공개 `save_trade`는 동일하게 승인된 viewer/editor/admin을 허용한다. 미승인·차단·비로그인 사용자, 관리자 전용 숨김/복원·사용자 승인, PRD 기존 수정 권한은 변경하지 않는다. 동시 수정 버전 검사, 날짜/객체 유효성 검사와 감사 기록을 유지한다. 서버 변경은 `supabase/site-trades-approved.sql`로 적용한다.


### 도면 현황 표와 최상단 보기 도구

철골보·슬래브의 확대·축소·도면 맞춤·현황 그래프·상세정보 버튼을 공종 선택과 같은 최상단 메뉴로 옮겼다. 두 도면은 하나의 공통 버튼 그룹을 사용하고, 선택 공종의 그래프·상세정보 상태를 버튼 이름과 눌림 상태에 반영한다. PRD·종합 현황판으로 전환할 때는 이 그룹을 숨긴다. 로딩·권한 변경 시 버튼 사용을 제한하며 기존 비저장 입력 보호를 유지한다.

철골보의 현황 요약은 도면 우측 상단 범례 아래 표로 표시한다. 전체 수량, 설치 기록, 완료 기록률, 중복 검토 그룹, 숨긴 보를 행으로 나누고 범례와 같은 배경·테두리·글꼴을 사용한다. 슬래브 표의 전체 영역·타설 기록·완료 기록률은 2026-10-06 아래의 면적 집계로 대체했다. 선택 공구에 맞춰 집계하며 숨긴 보는 기존과 같이 전체 수량·완료율에서 제외한다. 표와 범례는 도면 이동·확대의 영향을 받지 않고 클릭을 가로채지 않는다. 그래프 화면에서는 도면과 함께 숨긴다.

### 슬래브 종류·시공 날짜 (2026-10-03)

슬래브 기록에 데크슬래브·재래식 슬래브·가설 슬래브 종류와 데크 판개일·철근 설치일·타설일을 추가했다. 종류는 채움 색, 가장 나중에 입력된 시공 단계는 테두리 색으로 구분한다. 범례 아래 현황표에 단계별 날짜 입력 건수를 표시하며, 슬래브 범례·현황표는 작은 화면에서 스크롤할 수 있다. 종합 현황판과 완료율은 기존처럼 타설일을 사용한다.

기존 타설일은 `completed`에 그대로 보존하고 기존 종류는 미지정으로 둔다. 날짜는 필요한 항목만 입력할 수 있으며, 입력된 날짜끼리 판개→철근→타설 순서를 검증한다. 엑셀의 시공 기록에도 종류와 세 날짜를 포함한다. 승인된 viewer/editor/admin은 `site_save_slab_record`로 저장하며 실제 도면 영역, 날짜, 동시 수정 버전 및 감사 기록 검사를 유지한다. 서버 변경은 `supabase/site-slab-records.sql`이다.

슬래브 경계는 사용자가 추후 제공할 타설 조닝 영역으로 확정한다. 웹에서 경계를 그리는 기능은 당시 포함하지 않았다. 이 제한은 아래 v113 웹 경계 편집으로 대체한다. 새 영역 파일 반영 전까지 기존 자동 추출 후보 도면을 유지하며, 향후 도면 교체 시 저장 기록의 영역 연결을 확인해야 한다.

배포 전 화면·엑셀·인증 회귀검사와 저장 함수의 로컬 데이터베이스 검사를 수행한다. 서버 변경은 열·RPC 추가이므로 기존 클라이언트와 호환된다. 배포 후 저장·조회 실패가 확인되면 웹 배포를 이전 버전으로 되돌리고 추가된 열은 데이터 보존을 위해 유지한다.

### 슬래브 면적 진도율·오프닝·철골보 표시 연동 (2026-10-06)

현재 슬래브 타설 진도율은 **타설 완료 면적 ÷ (존 전체 면적 − 오프닝 면적)**이다. 앞 절의 슬래브 영역 개수·날짜 입력 건수 비율 설명은 이 방식으로 대체한다. 도면에 추출된 슬래브 후보의 면적 합을 분모로 쓰지 않고, 각 층의 10개 존 경계가 덮는 전체 면적을 사용한다. 존 경계가 겹치면 중복 면적은 한 번만 계산한다. 도면 좌표는 mm이며 면적은 m²로 표시한다.

종류에 `오프닝`을 추가했다. 일반 영역 또는 추가 검토 영역을 오프닝으로 저장하면 해당 도형을 존 경계로 잘라 면적을 공제한다. 여러 오프닝이 겹쳐도 한 번만 공제한다. 타설일·데크 판개일·철근 설치일이 저장된 영역의 면적을 같은 타설 대상 경계와 교차해 단계별 실적을 계산한다. 완료 영역끼리 겹치는 부분도 중복 집계하지 않고, 여러 존에 걸친 영역은 각 존의 교차 면적으로 나눈다. 빈 후보/날짜 없는 후보는 완료 면적에 포함하지 않는다. 추가 검토 표시 체크박스는 면적 집계에 영향을 주지 않으며, 저장된 오프닝은 체크를 꺼도 도면에 흰색·점선 테두리로 표시한다.

오프닝을 선택하면 시공 날짜 입력을 비활성화하고 공제 안내를 보여준다. 이미 저장된 날짜는 삭제하지 않고 실적 계산에서 제외한다. 슬래브 종류로 복원하면 보존된 날짜를 다시 사용한다. 공제 후 면적이 0이면 진도율은 `—`로 표시한다. 당시 슬래브 경계 그리기·자동 병합·재추출은 포함하지 않았다. 경계 그리기는 아래 v113에서 추가했다.

도면 범례 아래 표, 공구 탭, 공구별 그래프, 종합 현황판과 두 종류의 엑셀 다운로드는 같은 면적 계산을 공유한다. 층별로 먼저 면적을 계산한 뒤 합산하므로 같은 평면 좌표의 지하1층·지하2층 면적이 서로 합쳐지지 않는다. 아직 슬래브 조닝이 등록되지 않은 층은 집계 준비 중이며 현황판 합산에서 제외한다. 현재 슬래브 집계 범위는 지하1층이다.

철골보 숨김/복원은 동일 층의 공유 표시 상태를 사용하며 슬래브 도면의 보 배경에도 즉시 반영한다. 관리자의 `숨긴 보 표시` 옵션은 철골보 화면에서만 유효하다. 숨김은 기존 슬래브 영역을 삭제하거나 그 경계·면적을 변경하지 않는다. 향후 경계 편집 기능을 추가할 때도 숨긴 보는 경계 선택 후보에서 제외해야 한다.

`supabase/site-slab-openings.sql`은 종류 제약과 저장 함수의 허용값에 `opening`만 추가한다. 기존 날짜·입력 키·버전·감사 기록·권한을 유지한다. 서버 저장을 트랜잭션 안에서 검증 후 되돌려 실제 시공 기록을 보존했다. 로컬 DB에서 승인/차단 계정, 잘못된 종류·날짜, 버전 충돌, 감사 기록을 검증했다. 보안 점검 결과는 적용 전과 동일하다.

기하 연산은 MIT 라이선스의 `polygon-clipping` 0.15.7 브라우저 번들을 고정해 사용한다. 배포 원본은 https://registry.npmjs.org/polygon-clipping/-/polygon-clipping-0.15.7.tgz 이며 라이선스는 `vendor/polygon-clipping-LICENSE.md`에 보관한다. `tests/site-slab-area.test.cjs`는 존 전체 면적, 중복 오프닝·완료 영역, 존별 교차 면적, 내부 구멍 및 공제 후 0 면적을 검사한다. UI 회귀검사는 철골보 숨김/복원 연동과 오프닝 저장/복원 시 날짜 보존을 포함한다. 엑셀은 저장 후 다시 읽어 면적·공제·진도율·날짜가 유지되는지 확인한다.

복구가 필요하면 웹 커밋만 되돌리고 서버 종류 값과 시공 기록은 보존한다. 이전 클라이언트는 `opening`을 검증할 수 없으므로 오프닝 기록이 생긴 이후에는 이전 코드에 해당 허용값을 유지하는 수정이 필요하다.

### 슬래브 초기화·오프닝 기본값·영역 지정 안내 (2026-10-06, v112)

사용자 요청으로 등록된 슬래브 기록 5건의 이름·사양·메모·판개일·철근 설치일·타설일을 비웠고 종류를 오프닝으로 초기화했다. 원본 영역/철골보 도면은 유지한다. 초기화 전 전체 기록은 공개 저장소 밖의 로컬 파일과 기존 서버 감사 기록에 보관한다. 삭제 대신 저장 RPC를 사용해 버전을 올리므로, 초기화 전에 열린 입력 화면이 이전 버전으로 기록을 덮어쓰면 충돌로 거부된다. 초기화 후 날짜 및 필드 공란을 확인했고 PRD·철골보 기록의 체크섬이 전후 동일한 것도 확인했다.

앞 절의 기본 미지정 처리 방식은 이번 사용자 지정 기본값으로 대체한다. **존 전체에서 아직 실제 슬래브 종류를 지정하지 않은 면적은 오프닝으로 간주한다.** 기존 영역을 데크슬래브·재래식 슬래브·가설 슬래브로 지정해 저장하면 그 영역의 존 내부 면적이 타설 대상에 추가된다. 별도로 저장한 오프닝은 실제 슬래브와 겹쳐도 공제하며, 종류를 지정하지 않은 중첩 후보가 저장된 실제 슬래브를 지우지는 않는다. 구멍·미지정 빈 공간도 기본 오프닝에 포함해 초기 타설 대상 면적이 미세한 도면 틈 때문에 생기지 않는다. 초기화 직후 타설 대상/완료 면적은 0 m², 진도율은 `—`이다. 식은 여전히 타설 완료 면적 ÷ (존 전체 면적 − 오프닝 면적)이며 공구·현황판·엑셀이 같은 계산을 사용한다.

종류 선택의 첫 항목은 `오프닝 (기본)`이며 입력 기록이 없는 영역을 클릭해도 이 값으로 열린다. 오프닝 상태에서는 시공 날짜가 잠기며, 실제 슬래브 종류로 바꾸면 날짜 입력을 허용한다. 기존 형상을 선택하는 방법을 오른쪽의 `영역 지정 방법`에 안내한다: 공구 선택/확대 → 보 사이의 영역 안쪽 클릭 → 종류 선택 → 기록 저장. 안내는 선택 후에도 접었다 펼칠 수 있다. 당시에는 영역 경계를 바꿀 수 없었다. 이 제한과 안내는 아래 v113의 웹 경계 편집으로 대체한다. 추가 검토 영역은 기존 체크박스로 표시하며, 명시적으로 저장한 오프닝만 체크와 관계없이 표시한다.

검증은 미기록·빈 종류의 기본 오프닝 처리, 실제 슬래브 지정/해제, 중첩 후보와 명시적 오프닝의 우선순위, 판개/철근/타설 날짜 잠금 및 저장, 층별 면적 집계와 엑셀을 포함한다. 로컬 DB 검사는 초기화 후 버전 증가·공란·감사 기록·이전 버전 저장 거부를 확인한다.


### 웹 슬래브 경계 편집 (2026-10-06, v113)

자동 추출 후보가 실제 슬래브 구획과 다르므로, 웹에서 기존 경계를 고치거나 새 영역을 그릴 수 있도록 했다. 위 v112까지의 “경계 편집 불가” 안내는 적용되지 않는다.

- 기존 영역 안쪽 클릭 → **경계 수정** → 경계점 드래그. 경계선 클릭으로 점을 추가하고, 점을 선택한 뒤 **선택 점 삭제**로 제거한다. 내부 구멍이 있는 기존 영역은 내부 경계점도 같은 방식으로 수정할 수 있다.
- **경계 다시 그리기**는 같은 영역 키의 외곽을 새 꼭짓점으로 대체하며 기존 종류·사양·날짜·메모는 보존한다. 기존 내부 구멍은 새 경계로 대체되므로 시작 안내에 이를 표시한다.
- **새 영역 그리기** → 꼭짓점을 순서대로 클릭 → **경계 저장**. 보 끝점·교점·보선과 존 경계에 화면 10px 이내에서 맞춘다. 체크 해제 또는 Alt로 자유점을 사용한다. 첫 점을 다시 클릭하거나 Enter로 저장할 수도 있다. 휠 확대 및 빈 공간 드래그 이동을 계속 사용할 수 있다.
- 잘못된 기존 후보는 **이 영역 숨기기**로 도면·타설 면적·현황판·엑셀에서 제외한다. **숨긴 영역 복원** 목록에서 되돌릴 수 있으며 시공 기록은 남는다. 새 영역의 기본 종류는 오프닝이다. 종류·날짜는 경계 저장 뒤 별도로 기록 저장한다.
- **되돌리기**, **취소**, Esc를 제공한다. 경계 초안이 남아 있으면 층·공구·공종 전환 및 최신 기록/내보내기를 막고 저장 또는 취소를 안내한다. 로그아웃/접근 차단 시 도형·초안·복원 목록을 지운다.

철골보와 같은 표시 상태를 참조해 숨긴 보는 그리기 맞춤 후보에서 제외한다. 보 숨김 자체가 이미 저장한 슬래브 경계를 자동으로 바꾸지는 않는다. 수정한 도형은 동일한 면적 계산기로 현황표·존별 그래프·종합 현황판·엑셀에 반영한다. 자동 후보가 없는 지하2층에서도 존과 보 도면을 바탕으로 새 영역을 그릴 수 있으며 실제 저장된 영역이 생기면 해당 층을 현황판 면적 집계에 포함한다. 미지정 면적의 기본 오프닝 처리 및 면적 중복 제거는 v112와 동일하다.

서버 변경은 `supabase/site-slab-regions.sql`이다. 원본 `site_drawings.document`를 바꾸지 않고 `site_slab_regions`에 수정 형상/숨김/버전을 별도 저장한다. 승인된 viewer/editor/admin만 읽고 저장할 수 있으며 직접 테이블 쓰기는 금지한다. 저장 RPC는 단순 폐곡선, 유한 숫자 좌표, 교차·중복 점, 내부 구멍의 포함/겹침, 3~200점/경계·600점/도형 한도 및 존 좌표 범위 검사 후 반영한다. 원본 형상 그대로의 숨김/복원은 원본에 경계점·내부 구멍이 많은 경우도 허용한다. 원본을 변경하는 편집은 같은 점 개수 한도를 적용하므로 복잡한 원본은 경계 다시 그리기를 안내한다. 새 키는 UUID v4 형식으로 제한하며 기존 키는 원본 영역 또는 저장된 사용자 영역이어야 한다. 원본 영역/새 영역 모두 버전 충돌을 거부하고 변경 전후 형상을 비공개 감사표에 보관한다. 숨긴 영역의 날짜 저장은 거부하고 복원하면 보존된 기록을 다시 사용한다. 시공 기록 저장과 경계 저장은 같은 항목 잠금을 사용한다.

검증: 경계 생성/이동/점 추가·삭제/되돌리기/취소, 잘못된 형상 및 저장 실패 시 초안 보존, 층별 키와 기록 분리, 숨김/복원 후 면적 및 날짜 보존, 새 도형의 현황판/엑셀 합산, 보 맞춤과 숨긴 보 제외, 승인/미승인/차단 계정 및 감사 접근 차단을 로컬 화면·DB 검사로 확인한다. 서버 변경은 기존 엔드포인트를 유지하는 추가형이며 기존 페이지가 받는 도면은 그대로다.

복구 기준: 로그인·원본 도면 로드·경계 저장 중 핵심 동작이 실패하면 웹을 이전 커밋으로 되돌린다. 추가된 형상·감사표와 시공 기록은 보존한다. 이전 웹은 수정 형상을 표시하지 못하므로 복구 중 경계 수정을 중단하고 v113 이후 클라이언트로 복원해야 한다.


### 새 영역 우선 구획·겹침 미리보기 (2026-10-06, v115)

v113의 자유로운 중첩 저장 방식은 이번 구획 방식으로 대체한다. 슬래브 도면의 빈 공간을 클릭하면 **선택할 영역이 없습니다** 안내를 띄우며 공구·확대·이동·선택·입력 초안을 유지한다. 슬래브 공구 이동은 공구 탭/그래프에서 지정한다. 철골보의 공구 이름·경계 클릭 이동은 유지한다.

사용자가 선택한 정책은 **새 영역을 우선하고 기존 영역을 잘라내기**다. 새로 그리거나 편집한 형상을 실제 존 경계 안으로 자르고, 겹치는 기존 활성 영역에서 새 영역의 면적만 공제한다. 기존 형상이 여러 조각으로 나뉘면 같은 영역 키에 `geometry.parts`로 보관한다. 모든 조각은 종류·이름·사양·날짜·메모를 공유하며 클릭/편집/면적/현황판/엑셀은 모든 조각을 사용한다. 완전히 가려진 영역은 숨김으로 바꾸고 기록은 보존한다. 원본 DXF와 시공 기록은 변경하지 않는다. 확인하지 않은 추가 검토 후보는 대안 형상이므로 실제 구획의 절단 대상에서 제외한다. 기록이 있거나 직접 저장한 검토 영역은 포함한다.

**겹침 미리보기**는 저장 없이 새 경계를 주황, 주변의 조정 후 경계를 보라로 표시하고 조정·숨김 개수를 안내한다. **경계 저장**은 새 영역과 주변 경계를 한 번에 저장한다. 기존 영역·보·존 경계에 화면 10px 이내에서 맞추며, 기존 영역 경계를 우선한다. 맞춘 좌표는 반올림하지 않아 공유 경계에 미세한 틈을 만들지 않는다. Alt/체크 해제 시 자유점이다. 이는 가까운 경계를 정확히 붙이는 기능이며 의도적인 오프닝과 큰 미지정 빈 공간을 자동으로 채우지는 않는다. 경계 수정/다시 그리기로 기존 형상을 줄인 부분도 자동으로 다른 영역에 배정하지 않는다.

숨긴 영역을 복원할 때 현재 활성 영역과 겹치면 복원을 중단하고 필요한 부분을 새로 지정하도록 안내한다. 복원 검사와 저장 사이에 다른 사용자가 경계를 바꾸면 버전 충돌로 중단한다. 새 영역의 초기 종류는 오프닝이며 경계 저장 후 종류·날짜를 별도 저장한다.

`supabase/site-slab-partition.sql`은 추가형 RPC `site_save_slab_regions`를 제공한다. 승인 계정만 호출하며 층 단위 잠금, 전체 층의 경계 버전 스냅샷, 항목별 버전과 감사 기록을 사용한다. 잘못된 형상/권한/중복 키/동시 변경이 있으면 전체 배치를 되돌린다. 직접 테이블 쓰기는 계속 금지한다. 단일 숨김 RPC도 같은 층 잠금을 사용한다. 일반 그리기의 200점/경계·600점/도형 한도는 유지하고, 절단/다중 조각은 1,000점/경계·200개 조각·전체 2,000점 한도로 검증한다. 공유 경계의 기하 절단 및 조각 간 중첩 검사는 클라이언트에서 수행하며 서버는 각 조각의 유효성, 좌표 범위, 권한·버전과 일괄 저장을 검증한다. 면적 1e-9 m² 이하의 수치 잔여 조각은 제외한다.

검증은 빈 클릭의 뷰/선택/입력 보존, 새 영역 우선 절단, 내부 구멍 및 분리 조각, 완전 가림/복원 충돌, 날짜·메모 보존, 정확한 공유 좌표, 존 외곽 절단, 층별 면적·내보내기, 저장 실패/버전 충돌 시 배치 전체 보존, 승인/미승인/차단 계정과 비공개 감사 접근을 포함한다. 실제 지하1층 10개 존의 경계 절단도 로컬 도면으로 확인한다. 서버 저장은 트랜잭션 내 실행 후 되돌려 사용자가 만든 형상과 기록을 보존한다.

복구 시 경계 편집을 중지하고 배포를 되돌릴 수 있지만, `parts`를 이해하지 못하는 v114 이전 화면은 여러 조각 중 첫 조각만 표시하므로 실제 다중 조각 저장 이후에는 v115의 형상 해석 코드를 유지해야 한다. 서버 데이터/시공 기록/감사 기록은 보존한다.

## PRD 자재 상세·공경 정정 및 완료 명칭 (2026-10-06, v117)

자재 엑셀의 A1/A2/A3 공별 행을 기존 도면 번호에 정확히 연결해 상세 정보에 표시한다. 기둥·근입장 규격, 길이, TOP/레벨, 중량, JOINT, 제작 상태, 반입 예정일·실제 반입일, 근입일, 검측 일자·차순, 호기·근입 차순 및 특이사항을 원본 파일·시트·행·셀과 함께 보관한다. 원본에 없는 단위와 값은 만들지 않는다. 근입일은 타설일과 별도이며, 명시된 연도는 유지하고 연도 없는 날짜의 추정은 표시한다. 붉은색 예정 반입일과 미회신 검측을 실제 반입 실적으로 취급하지 않는다. A2 B열의 두 제목은 원본 그대로 구분해 표시한다.

353공의 상세 정보를 반영하고, 검토를 통과한 빈 반입일 349건을 채웠다. 날짜 역전 4공의 반입일은 원본 상세만 보존하고 실적 입력을 보류했다. 기존 천공일과 다른 5공은 기존 날짜를 유지했다. 삭제 표시된 미연결 행은 새 공으로 생성하지 않는다. 원본 집계 수식은 사용하지 않고 공별 행으로 확인했다. 사용자 확인에 따라 342공의 `diameter`와 공경 표시 레이어를 엑셀 값으로 정정했다. 원본 도면의 기호 크기·좌표·번호·존 경계·다른 공종은 유지한다. 기존 천공일·타설일·메모는 유지했고, 변경 전후 기록 및 공경은 비공개 감사 기록에 보관한다. 실제 공별 자료는 공개 저장소에 넣지 않는다.

`supabase/prd-materials.sql`은 기존 PRD 표에 `material_details` 객체를 추가한다. 기존 승인 계정 조회 정책을 그대로 사용하며 직접 쓰기는 금지한다. 기존 날짜·메모 저장 RPC는 이 열을 덮어쓰지 않는다. 가져오기는 전체 버전과 번호·공경을 확인하고 한 트랜잭션으로 반영했다. 이후 최신 기록 조회·계정 변경·로그아웃은 상세 자료도 함께 갱신/제거한다. 원본 대조 사항은 가져온 시점의 비교 기록이며 확인 필요 필터·표·도면에 포함한다. 엑셀에는 공별 기록 외에 자재·검측 상세와 원본 대조 확인 시트를 추가했다.

PRD의 상태·진도율·주간 실적·종합 현황판·다운로드에서 완료 명칭은 **시공 완료**로 통일한다. 완료를 판단하는 저장 날짜와 집계 방식은 유지한다. 슬래브의 타설 완료 명칭은 그대로 사용한다.

검증은 원본 연결·날짜 역전 및 충돌 보존·공경 대조, 승인/미승인/차단 조회·직접 쓰기 차단, 기존 RPC의 원본 자료 보존·버전 충돌·감사 기록, 새 정보 갱신·로그아웃 제거, 엑셀의 실제 날짜/원본 연도/문자열 보존을 포함한다. 오류 시 웹을 이전 커밋으로 되돌릴 수 있으며 추가 열과 가져온 기록은 보존한다.

## PRD 규격 입력 정리 (v118 · 2026-10-06)

앞 절의 읽기 전용 자재·일정·검측 상세 패널은 **천공 직경(mm), 기둥 규격, 근입장 규격** 세 입력란으로 대체한다. 중량·JOINT·TOP·길이 등 다른 가져온 항목과 원본 대조 패널은 화면과 현황 엑셀에서 제외한다. 기존 공구·부재명·타입, 천공일·반입일·타설일(완료일)·메모는 유지한다. 현황 엑셀의 공별 기록은 세 규격의 현재 저장값을 내보낸다.

최초 표시는 가져온 엑셀 값을 사용하며, 엑셀이 없는 공은 도면의 공경과 빈 규격을 사용한다. 수정값은 `site_prd_records.specifications`에 저장하고 이후 원본보다 우선한다. 사용자가 값을 비워 저장한 경우에도 원본으로 되돌리지 않는다. 천공 직경은 양수 또는 미입력, 두 규격은 각각 120자 이내다. 도면의 원 위치·기호 크기·식별자는 수정하지 않는다. 기존 가져오기 원본은 서버에 보존한다.

`supabase/prd-specifications.sql`의 새 저장 RPC는 기존 PRD 수정 권한(editor/admin), 공 존재 여부, 버전 충돌과 날짜 순서를 확인하고 날짜·메모·규격을 한 트랜잭션에서 저장·감사한다. 조회 전용 계정은 세 규격도 조회만 가능하다. 기존 날짜 저장 RPC는 새 규격을 덮어쓰지 않아 이전 화면과 호환된다. 검증은 원본 초기값·수정/공백 보존·다른 공 선택·충돌 시 초안 보존·최신 기록·로그아웃·실제 숫자/문자열 엑셀 내보내기·권한 차단을 포함한다. 웹 롤백 시 추가 열과 수정값은 보존한다.

자재가 천공 전에 들어올 수 있으므로 **자재 반입일과 천공일의 선후관계는 제한하지 않는다.** 반입 먼저·천공 먼저 모두 저장 가능하며 두 날짜의 순서를 오류로 표시하지 않는다. 타설일(완료일)이 입력된 경우에는 두 작업일보다 빠르지 않아야 한다.

## 슬래브 부재표 연결

슬래브 도면의 `slabCatalog`는 승인된 사용자에게만 전달되는 도면 문서 안에 저장합니다. 공개 코드에는 현장 부재표를 포함하지 않습니다. 항목은 `code`, `thickness_mm`, `type`, 선택적인 `attributes: [{label, value}]`로 구성합니다. 잘린 표나 미표기 값은 추정하지 않습니다.

영역 상세에는 **슬래브 부재표** 선택만 표시하며, 별도의 사양 입력칸과 상세 배근 설명은 표시하지 않습니다. 항목을 선택하면 부재명·두께·데크 형식을 기존 저장 필드에 넣고 **기록 저장**으로 저장합니다. 구역 이름·슬래브 종류·날짜·경계는 별도로 유지합니다. 이전에 직접 입력한 사양은 **기존 입력** 항목으로 유지하며, 부재표 선택이나 미지정으로 변경할 수 있습니다.

엑셀 다운로드의 기존 **시공 기록**에 저장된 사양을 포함하고, 해당 층에 등록된 표가 있으면 **슬래브 부재표** 시트를 추가합니다. 층 전환 및 로그아웃 시 이전 층의 부재표 선택 목록을 제거합니다. 부재표 등록만으로 평면 경계를 지정하거나 타설 대상 면적을 바꾸지 않습니다. 이미지와 기존 도면에서 공통 경계를 확인할 수 없을 때는 원본 평면이 필요합니다.

기존 도면의 보·영역 경계와 이미지의 배치가 대응하는 구간은 기존 좌표를 사용해 연결할 수 있습니다. 등록한 구역은 상세 패널의 **규격 연결 영역 → 연결 구간 도면 맞춤**으로 바로 확인하며, 목록의 구역을 선택하면 해당 영역과 시공 정보를 엽니다. 충분히 확대하면 도면에도 부재명이 표시됩니다. 영역 색은 부재명 대신 시공 단계와 슬래브 종류로 구분합니다. 데크 판개는 파랑, 철근 배근은 주황으로 종류에 관계없이 동일하게 표시합니다. 미착수와 타설 완료는 데크슬래브(초록), 재래식 슬래브(보라), 가설 슬래브(분홍)로 나누고, 미착수는 연하게, 완료는 진하게 표시합니다. 타설 완료 → 철근 배근 → 데크 판개 순으로 최근 단계가 우선합니다. 부재명은 도면에 계속 표시하며, 오프닝은 흰색 점선으로 유지합니다. 경계 수정은 기존 영역 저장·겹침 제거·감사 기록 방식을 사용하며, 원본 도면과 기존 시공 날짜·메모는 유지합니다.
