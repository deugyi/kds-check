# 공정별 진행현황

협력사의 아침 작업계획과 실제 공사 수량을 카카오톡 채널 또는 사이트원에서 접수하고 지정 감독자가 승인합니다. 기존 도면의 PRD·철골보·슬래브 기록과 별도로 관리합니다. [카카오톡 채널 연결 안내](site-kakao-channel.md)에 업체 담당자 연결, 메시지 양식, 계획별 결과 회신 절차가 있습니다.

## 업체와 감독자 설정

관리자 계정으로 **공정별 진행현황 → 업체 설정**에서 업체명, 남측·북측 현장, 담당 감독자 계정을 등록합니다. 감독자는 Google 로그인 후 현장 이용 승인을 받아야 목록에 표시됩니다. 관리자도 자신에게 지정된 업체만 승인할 수 있습니다.

업체 담당자의 카카오톡은 **카카오톡 채널 설정 → 업체 연결 코드**로 연결합니다. 발급 문구는 24시간 동안 한 번 사용할 수 있으며 담당자 교체 시 카카오 연결을 해제하고 새 코드를 발급합니다. 계정 이름만으로 업체를 식별하지 않습니다.

## 접수와 검토

**실적 직접 입력·보완**에서 업체·실제 작업일·층·공구·공정·수량·단위를 입력합니다. 카카오톡 채널로도 같은 수량 양식을 접수합니다. 아침계획 원문을 가져오거나 채널로 보내면 인원·장비·반입·작업계획을 구분하고, 계획에 연결한 작업결과에서 실제 수량과 잔여·미실시 사유를 확인합니다. 계획 자체는 완료 실적에 더하지 않습니다.

| 상태 | 처리 |
|---|---|
| 감독자 승인 대기 | 원문과 실제 수량 검토. 공식 수량·엑셀에서 제외 |
| 보완 요청 | 사유를 남겨 재제출 요청. 기존 기록과 이력 보존 |
| 승인됨 | 지정 감독자 승인 후 공식 실적·엑셀에 반영 |

같은 업체·작업일에 공종이 다르면 별도로 접수할 수 있습니다. 같은 공종의 층·공구별 항목은 한 건에 모읍니다. 작업 없음은 업체의 당일 전체를 뜻하며 같은 날짜의 실제 수량과 함께 등록하지 않습니다. 승인된 건은 감독자가 승인 취소·보완 요청한 후 수정합니다. 다른 사람이 먼저 수정하면 최신 기록을 조회하도록 안내합니다.

## 조회와 엑셀

**승인된 실적**에서 기간·업체별 공정·단위로 합산합니다. **승인 실적 엑셀**은 공정별 실적, 업체별 실적, 승인 실적 목록을 제공합니다. 계획에 연결된 결과가 있으면 계획별 작업결과 시트도 포함합니다. 서로 다른 단위를 환산하거나 합산하지 않습니다.

**등록 상태**는 조회 종료일의 업체별 승인됨·감독자 승인 대기·보완 요청을 함께 표시하고 접수가 없으면 미접수로 표시합니다. 카카오톡 업체 연결 여부도 확인할 수 있습니다. 카카오 미회신 알림은 알림톡·승인 템플릿 연결이 필요한 별도 과제이며 현재 자동 발송하지 않습니다.

## 텔레그램 기능 종료

텔레그램 설정·담당자 연결·접수·알림 발송을 제거했습니다. 외부 수신 연결을 해제하고 자동 알림 스케줄·관련 RPC·서버 인증값을 제거합니다. 이전 주소로 재시도하는 요청은 HTTP 410으로 거절하며 재설정할 수 없습니다. 기존 텔레그램 실적·승인·감사·발송 이력은 보존하고 이전 접수 경로로 표시합니다. 기존 결과는 계속 조회·승인·엑셀 출력할 수 있습니다.

## 서버와 검증

기존 Google 로그인과 현장 이용 권한을 사용합니다. 공개 테이블은 RLS를 적용하고 쓰기는 권한·상태·버전을 검사하는 RPC로 제한합니다. 카카오 스킬 인증값은 관리자만 조회하며 서버 Vault에 보관합니다. 도면 부재·슬래브 경계와 완료 상태를 이 기능에서 변경하지 않습니다.

`npm ci` 후 `npm test`로 UI·양식·승인·엑셀·제거한 접수 경로를 검사합니다. `PGLITE_MODULE`을 지정해 `node --test supabase/kakao-security.test.cjs`를 실행하면 카카오 접수와 텔레그램 종료 마이그레이션의 데이터·권한 검증을 수행합니다. 이전 `site-progress-db.sql` 및 `site-progress-multiple-processes-db.sql`은 텔레그램이 있던 시점의 마이그레이션 검사이므로 현재 운영 DB에 실행하지 않습니다.
