# 공정별 진행현황

카카오톡 채널의 아침 작업계획·실적 접수 및 계획별 결과 회신은 [카카오톡 채널 연결 안내](site-kakao-channel.md)를 참고합니다. 일반 단체방을 읽는 방식은 아닙니다. 아침 계획은 실제 수량과 구분하며 감독자 승인 전 공식 실적에서 제외합니다.

협력사 실적 접수 → 지정 감독자 승인 → 정식 등록을 관리합니다. 상단 **공정별 진행현황**에서 토사 반출·데크 슬래브·철골보·콘크리트 타설 등 실적을 수량과 단위로 기록합니다.

## 처음 설정하기

1. 사이트원 관리자 계정으로 로그인합니다. **업체·텔레그램 설정**에서 업체명, 남측·북측 현장, 감독자 계정을 등록합니다. 감독자는 먼저 Google 로그인 후 기존 관리자 메뉴에서 현장 이용 승인을 받아야 계정 목록에 나타납니다. 관리자가 모든 업체의 감독자로 자동 지정되는 것은 아닙니다.
2. 텔레그램의 공식 **@BotFather**에서 `/newbot`을 보냅니다. 봇 이름은 `사이트원`, 사용자 이름은 사용 가능한 영문 이름(예: `seoripul_siteone_bot`)으로 지정합니다. 사용자 이름은 `bot`으로 끝나야 합니다.
3. 발급된 토큰을 사이트원의 **BotFather 토큰**에 붙여 넣고 **봇 연결하기**를 누릅니다. 수신 주소와 인증키는 자동 설정됩니다. **연결 확인**으로 상태를 확인합니다. 토큰은 서버 Vault에 보관하며 브라우저에 다시 반환하지 않습니다. 채팅·메일·저장소에 토큰을 올리지 않습니다.
4. 업체별 **업체 연결 링크**를 협력사 담당자에게 전달합니다. 담당자는 링크를 열고 **시작**을 누릅니다. 링크는 24시간 동안 한 번만 사용하며 계정당 한 업체에 연결합니다. 담당자 교체는 **업체 연결 해제** 후 새 링크를 발급합니다.
5. 감독자는 본인 사이트원 계정으로 로그인해 해당 업체의 **내 텔레그램 연결**을 누르고 시작합니다. 이 연결은 승인 요청 알림을 받는 용도이며 승인은 사이트원에서 합니다.
6. 업체별 알림 요일·시각을 정하고 **자동 알림**을 켠 뒤 **설정 저장**합니다. 초기값은 꺼짐, 월~토, 17:00입니다. 한국 시간으로 5분마다 상태를 확인합니다. **등록 상태**에서 양측 연결 여부를 확인합니다.

봇을 아직 연결하지 않아도 직접 입력·감독자 승인·승인 실적 조회·엑셀은 사용할 수 있습니다. 기존 관리자·감독자 권한을 부여하거나 업체 정보를 임의로 등록한 것은 아닙니다. 운영자가 실제 계정과 업체를 설정합니다.

## 협력사 전송 양식

첫 줄은 실제 작업일 `YYYY-MM-DD`, 나머지 줄은 **층·위치 / 공구 / 공정 / 수량 / 단위**입니다. 업체는 사전 연결한 계정에서 식별합니다.

```text
2026-10-12
외부 / 전체 / 토사 반출 / 120 / m3
지하1층 / B2 / 데크 슬래브 / 50 / 장
지하1층 / B2 / 철골보 / 20 / 부재
지하1층 / B2 / 콘크리트 타설 / 35 / m3
비고: 특이사항 없음
```

수량은 양식 예시입니다. 실제 날짜·실적으로 바꿉니다. 최대 50개 항목, 소수점 셋째 자리까지 지원하며 대·장·부재·공·개는 정수로 입력합니다. `m3`·`㎥` → `m³`, `m2`·`㎡` → `m²`, `톤` → `t`로 표기만 통일하고 단위 간 환산은 하지 않습니다.

작업이 없는 날도 제출하고 승인을 받습니다.

```text
2026-10-12
작업 없음
비고: 우천으로 작업 없음
```

같은 업체·작업일에도 **공종이 다르면 별도 메시지로 추가 접수**할 수 있습니다. 예를 들어 10월 12일 토사 반출을 접수한 뒤 같은 날짜의 철골보 실적을 따로 전송할 수 있습니다. 각 접수 건은 따로 승인합니다. 한 메시지에 여러 공종을 함께 넣는 방식도 사용할 수 있습니다.

같은 공종의 층·공구별 항목은 한 메시지에 모아 보냅니다. 이미 접수한 공종을 다시 입력하면 중복 접수를 막고 보완 방법을 안내합니다. 내용을 바꾸려면 첫 줄에 `/수정`을 넣고 날짜와 **기존 건에 포함된 공종의 전체 항목**을 다시 전송합니다. 공종 자체를 바꾸거나 일부 공종을 삭제하려면 사이트원에서 기존 건의 **내용 보완·재제출**을 사용합니다. 승인된 건은 감독자가 **승인 취소·보완 요청**한 뒤 수정합니다.

```text
/수정
2026-10-12
외부 / 전체 / 토사 반출 / 125 / m3
비고: 반출량 보완
```

봇과 **개인 1:1 대화**로 전송합니다. 그룹 메시지는 접수하지 않습니다. **입력 안내** 버튼으로 양식을 다시 확인할 수 있습니다. 사진·엑셀 첨부나 자유로운 문장의 AI 해석은 이번 구현에 포함하지 않았습니다.

## 접수·승인·집계

| 상태 | 처리 |
|---|---|
| 감독자 승인 대기 | 접수한 상태. 공식 수량·엑셀에서 제외 |
| 보완 요청 | 감독자가 사유를 남겨 재제출 요청. 기존 원문과 이력 보존 |
| 승인됨 | 지정 감독자가 승인. 공식 실적 현황과 엑셀에 반영 |

**감독자 승인 대기**에서 건을 열어 원문·수량을 확인합니다. 지정 감독자에게만 **승인·정식 등록**과 **보완 요청**이 표시됩니다. 서버에서도 계정을 검사합니다. 관리자는 전체 접수와 업체 설정을 관리하며 자신에게 지정된 업체에서만 승인합니다.

동일 업체·작업일에 공종이 겹치지 않는 여러 실적 건을 접수할 수 있습니다. 한 건 안에는 같은 공종의 층·공구별 항목 또는 여러 공종을 함께 둘 수 있습니다. 작업 없음은 그 업체의 당일 전체를 뜻하므로 같은 날짜의 실제 실적과 함께 등록하지 않습니다.

메시지 재시도로 실적을 중복 생성하지 않습니다. 기존 건의 **내용 보완·재제출**은 선택한 실적 건만 수정합니다. 먼저 수정된 건은 버전 충돌을 알리고 덮어쓰지 않습니다. 한 공종을 승인해도 같은 날짜의 다른 공종은 기존 승인 대기·보완 상태를 유지합니다.

**승인된 실적**은 기간·업체별 공정·단위로 합산합니다. **승인 실적 엑셀**은 공정별 실적, 업체별 실적, 승인 실적 목록의 세 시트입니다. 실적 목록에는 감독자 승인 시각과 승인 상태가 표시됩니다. 다른 단위를 합산하지 않습니다. 수량만으로 기존 도면의 특정 부재를 완료 처리하거나 기존 도면 수량을 새 접수에 다시 더하지 않습니다.

## 미등록 알림

**등록 상태**는 조회 종료일의 업체별 승인됨·감독자 승인 대기·보완 요청 건수를 함께 표시합니다. 당일 접수 건이 하나도 없으면 미접수입니다. 자동 알림은 한국 시간 당일 작업일에 설정 요일·시각을 적용합니다.

| 상태 | 알림 |
|---|---|
| 미접수 | 협력사에 실적 전송 요청 |
| 감독자 승인 대기 | 지정 감독자에 확인·승인 요청 |
| 보완 요청 | 협력사에 보완·재제출 요청 |
| 승인됨 | 입력·승인 요청 대상에서 제외 |

미접수 요청은 업체·작업일 기준, 승인·보완 요청과 결과 안내는 실적 건·상태·버전 기준으로 한 번만 생성합니다. 알림에는 해당 공종을 표시합니다. 한 공종을 승인해도 다른 건의 승인 요청은 취소하지 않습니다. 전송 실패는 최대 3회 재시도하고 **알림 내역**에 기록합니다. 연결 해제·업체 중지·감독자 이용 권한 중지는 대기 발송에도 적용됩니다.

## 서버·검증

- 기존 Google 로그인, 현장 이용 권한을 사용하고 도면·부재·슬래브 시공기록을 변경하지 않습니다.
- 공개 테이블은 RLS와 읽기 권한을 적용합니다. 쓰기는 권한·상태·버전을 검사하는 RPC에서만 수행합니다. 비공개 이력·연결·알림은 `site_progress_private`, 봇 토큰·수신 및 스케줄 인증키는 Vault에 둡니다.
- Edge Function `site-process-bot`은 텔레그램 수신 인증키, 스케줄 인증키, 관리자 Google 세션을 각각 검사합니다. `verify_jwt=false`여도 익명 접근을 허용하지 않습니다.
- 스케줄 `site-progress-notifications`는 토큰이 없으면 아무 메시지도 전송하지 않습니다. 관리자의 설정 저장으로 업체별 알림을 켭니다.
- `npm ci` 후 `npm test`로 검사합니다. `tests/site-progress-db.sql`은 권한·승인·중복·알림을, `tests/site-progress-multiple-processes-db.sql`은 같은 날짜의 다른 공종 접수·개별 보완·승인·알림을 검사하고 모든 검증 데이터를 롤백합니다.
- GitHub Pages는 `.nojekyll`로 정적 파일을 제공하여 공유 스크립트 `_shared` 경로도 게시합니다.

공식 참고: [Telegram 봇 생성](https://core.telegram.org/bots#how-do-i-create-a-bot), [Webhook](https://core.telegram.org/bots/api#setwebhook), [Supabase 스케줄](https://supabase.com/docs/guides/functions/schedule-functions).
