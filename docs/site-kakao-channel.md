# 카카오톡 채널로 사이트원에 접수하기

사이트원 전용 **카카오톡 채널·챗봇**에서 업체가 보내는 아침 작업계획과 실제 수량을 접수합니다. 기존 일반 단체방에 봇을 넣거나 단체방 대화를 읽는 방식은 아닙니다. 현재 채널이 없으면 아래 절차로 채널과 봇을 만든 뒤 연결합니다.

## 채널과 접수 서버 연결

1. [카카오톡 채널 관리자센터](https://center-pf.kakao.com/)에서 사이트원 채널을 만듭니다. 프로필과 운영 정보를 확인해 등록합니다.
2. 카카오 챗봇 관리자센터에서 새 카카오톡 봇을 만들고, 해당 운영 채널을 연결합니다. 봇 ID와 `https://pf.kakao.com/...` 채널 주소를 확인합니다.
3. 사이트원 관리자 계정으로 로그인합니다. **공정별 진행현황 → 카카오톡 채널 설정**에서 봇 ID와 채널 주소를 넣고 **접수 사용**을 선택한 뒤 **설정 저장·인증키 확인**을 누릅니다. 채널을 만드는 중이면 접수 사용을 끈 상태로 인증키부터 발급할 수 있습니다.
4. 카카오 챗봇 관리자센터에서 `사이트원 접수` 스킬을 만듭니다. URL은 사이트원에 표시되는 주소를 사용합니다.

   ```text
   https://qbrwzldrlwtiawgzwvit.supabase.co/functions/v1/site-kakao-bot
   ```

5. 스킬의 **헤더값·테스트 헤더값**에 `x-siteone-kakao-key`를 등록합니다. 사이트원에서 **발급된 인증키 보기 → 인증값 복사**를 누르고 카카오의 두 입력란에 붙여 넣습니다. 인증값은 관리자센터에서만 사용하고 채팅·메일·저장소에 올리지 않습니다. 사이트원의 인증키 조회·복사는 관리자에게만 표시됩니다.
6. 시나리오 화면의 정보가 모두 로드된 후 **기존 폴백 블록**을 열어 같은 스킬을 연결하고 **스킬 데이터 사용**으로 설정합니다. 기본 블록을 새로 만들면 `기본 블럭은 유일해야 합니다` 오류가 발생할 수 있습니다. 기존 블록의 주소에는 실제 블록 ID가 있어야 합니다. `입력 안내`, `오늘 계획`, `회신 안내`와 긴 원문·실적 양식은 모두 폴백을 통해 서버에서 처리하므로 별도 명령 블록이 없어도 됩니다.
7. 스킬 테스트와 봇 테스트 후 운영 채널에 봇을 배포합니다. 테스트 화면은 인증된 서버 응답만 확인하고 업체 연결·시공 기록을 저장하지 않습니다. 봇 테스트가 운영과 다른 봇 식별값을 사용해도 고정 안내만 응답하며 실제 접수에서는 설정한 봇과 담당자 식별값을 검증합니다. 사이트원의 **접수 서버 확인** 역시 서버 설정의 준비 상태이며 실제 채널 배포·업체 연결의 확인을 대신하지 않습니다.

## 업체 담당자 연결

사이트원에서 실제 업체와 담당 감독자를 먼저 등록합니다. 카카오 설정의 업체 행에서 **업체 연결 코드**를 누르면 24시간 동안 한 번 쓸 수 있는 문구가 나옵니다. 담당자에게 문구를 전달하고 해당 담당자가 사이트원 채널의 개인 대화에 보냅니다.

```text
연결 발급된코드
```

봇이 업체명을 알려주며 연결 완료를 응답합니다. 이후 메시지는 연결된 업체에만 접수합니다. 업체명이나 닉네임만으로 다른 업체로 제출할 수 없습니다. 담당자가 바뀌면 관리자 화면에서 연결을 해제하고 새 코드를 발급합니다. 연결 해제는 기존 자료를 삭제하지 않습니다.

## 아침 작업계획

날짜·업체명·출력인원·장비·작업내용·자재반입·신규자 항목이 있는 아침 메시지를 그대로 보내면 정리해 접수합니다. 웹의 **아침 메시지 가져오기**에서도 같은 내용을 붙여 넣고 확인한 뒤 접수할 수 있습니다.

```text
2026년 10월 14일 수요일
1. 업체명: 사이트원에 등록한 실제 업체명
2. 출력인원
- 총원: 실제 총원명
- 직종: 실제 인원명
3. 장비
- 장비명·규격 실제대수대
4. 작업내용
- B2 B1F 예정 작업
5. 자재반입
- 자재·운송차량 내용
6. 신규자
- 신규자 보고 내용
```

위 문구의 자리 표시자는 실제 보고값으로 바꿉니다. 총원과 인원 분류 합계가 다르면 원문을 확인하도록 안내합니다. B1F는 지하1층으로 표기를 통일하고 미기재 층·위치·물량을 추정하지 않습니다. 차량 대수와 자재 자체 수량도 구분합니다. 아침의 예정 작업은 완료 실적에 더하지 않습니다.

아직 작업결과가 접수되지 않은 계획을 고치려면 `/계획수정`과 `계획버전: 현재 번호`를 함께 보냅니다. 작업결과가 접수된 계획은 잠그고 결과를 보완합니다.

## 실제 수량 접수

기존 직접 입력·텔레그램과 같은 수량 양식을 카카오에서도 받습니다. 날짜는 실제 작업일이며 수량과 단위를 명시합니다.

```text
YYYY-MM-DD
층 / 공구 / 실제 공정 / 실제 수량 / 단위
비고: 특이사항
```

작업이 없으면 실제 날짜 다음 줄에 `작업 없음`을 보냅니다. 같은 날짜에 공종이 다르면 별도로 접수할 수 있으며 같은 공종의 층·공구별 항목은 한 건에 모읍니다. `/수정`은 기존 날짜·공종의 실적을 보완합니다. 승인된 건은 감독자가 보완 요청한 후 수정할 수 있습니다.

## 아침계획에 대한 작업결과 회신

채널에서 `오늘 계획`으로 접수 내용을, `회신 안내`로 양식을 확인합니다. 다른 날짜는 `회신 안내 YYYY-MM-DD`처럼 지정합니다. 계획번호마다 완료·일부 완료·미실시를 입력합니다. 설치·용접 등은 같은 계획번호로 여러 행을 쓸 수 있습니다.

```text
작업결과
YYYY-MM-DD
계획버전: 현재번호
1 / 일부 완료 / 실제 세부 작업 / 실제 수량 / 단위 / 남은 작업
2 / 미실시 / - / - / - / 미실시 사유
추가 / 층 / 공구 / 계획에 없던 실제 작업 / 실제 수량 / 단위 / 비고
```

완료 항목의 사유가 없으면 마지막 칸에 `-`를 넣습니다. 일부 완료·미실시는 사유가 필요합니다. 실제로 진행한 작업의 수량은 0보다 커야 하며 대·장·부재·공·개·개소는 정수로 보고합니다. 단위가 다른 수량은 환산하거나 합산하지 않습니다. 모든 계획이 미실시이고 추가 실적도 없으면 당일 작업 없음으로 접수하므로, 다른 실제 작업이 있었다면 추가 행에 함께 기입합니다.

기존 계획별 회신을 고치려면 `작업결과수정` 양식에 최신 `계획버전`과 `실적버전`을 넣습니다. 회신 안내에 현재 번호가 표시됩니다. 승인된 건은 지정 감독자가 승인 취소·보완 요청한 뒤 수정합니다.

## 사이트원 검토와 집계

- **아침계획·회신**: 원문, 인원·장비·반입 보고, 예정 작업, 계획별 결과를 확인합니다.
- **감독자 승인 대기**: 실제 수량과 잔여·미실시 사유를 검토합니다. 지정 감독자만 승인하거나 보완 요청합니다.
- **승인됨**: 공식 실적 수량과 승인 실적 엑셀에 반영합니다. 카카오톡 접수 경로와 계획 항목번호를 함께 남깁니다. 계획에 연결된 승인 결과가 있으면 계획별 작업결과 시트도 출력합니다.

계획 물량이 없는 메시지에는 물량 달성률을 만들지 않습니다. 새 접수만으로 기존 도면 부재를 완료 처리하지 않으며 같은 공종의 중복 접수를 방지합니다. 카카오 접수 기록과 업체·계획·실적의 연결은 비공개 이력으로 보관합니다.

## 미회신 알림과 지원 범위

이 연결은 채널에 들어온 메시지의 **접수·즉시 응답**입니다. 카카오에서 먼저 미회신 알림을 보내려면 비즈니스 채널·공식 딜러사의 **알림톡** 및 승인 템플릿을 별도로 연결해야 합니다. 기존 텔레그램의 알림 설정은 그대로 유지합니다. 채널·봇·실제 업체·감독자·알림 설정은 운영자가 준비하고, 아침의 실제 업체 자료를 임의로 등록하지 않습니다.

사진·파일 첨부나 자유문장 수량 추정은 하지 않습니다. 정해진 아침 양식과 수량·작업결과 양식을 사용하며 확인되지 않은 단위·물량은 접수하지 않습니다.

## 개발 검증

`npm test`에 카카오 접수·아침 계획·실적 회신 UI 검사가 포함됩니다. PostgreSQL 검사는 `PGLITE_MODULE`로 PGlite 경로를 지정한 뒤 `node --test supabase/kakao-security.test.cjs`로 실행합니다. 실제 Supabase의 `tests/site-kakao-db.sql`은 트랜잭션에서 검증하고 모든 입력·연결·설정을 롤백합니다. 검증 SQL은 메시지를 발송하지 않습니다.
