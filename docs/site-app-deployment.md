# 사이트원 통합 웹앱 — 남측 / 북측

운영 주소: **https://deugyi.github.io/siteone/**

운영 저장소: **https://github.com/deugyi/siteone**

회사 웹앱에는 통합 주소 하나를 등록하고, 앱 상단의 **남측 / 북측** 메뉴로 현장을 전환한다. 최초 화면은 남측이다. `#north`를 붙인 주소는 북측으로 바로 열린다. 메뉴를 바꿔도 같은 앱 안에서 기존 계정의 로그인 상태를 유지한다.

## 기존 주소

- https://deugyi.github.io/siteone-south/ → 통합 앱의 `#south`
- https://deugyi.github.io/siteone-north/ → 통합 앱의 `#north`

기존 남측·북측 저장소의 main 소스와 이력은 보존한다. Pages는 해당 저장소의 `redirect` 브랜치를 사용해 통합 앱으로 안내한다. 앞으로 운영 화면 수정·배포는 `siteone` 저장소 한 곳에서 수행한다.

기존 https://deugyi.github.io/kds-check/ 는 구조 검토 프로그램과 후속 개발 원본으로 유지한다.

## 현재 기능 범위

- 남측: 기존 PRD·철골보·슬래브 도면, 시공기록, 종합 현황판, 실적 보고 및 엑셀 출력.
- 북측: 북측 전용 시공 현황. 현재 북측 도면과 시공기록은 준비 중이며, 남측 자료를 대신 표시하지 않는다.
- 공정별 진행현황·아침계획·협력사 접수·감독자 승인·카카오 설정은 추후 과제로 운영 앱에서 제외한다. 원본 코드와 기존 서버 기록은 보존한다.
- 남측 PRD 입력 또는 철골·슬래브 편집 중 현장을 전환하면 기존 저장·편집 확인 절차를 먼저 실행한다. 취소되거나 저장할 수 없으면 현재 화면을 유지한다.
- 데이터베이스와 계정 권한은 변경하지 않는다. 메뉴 선택은 현장 표시 범위이며 사용자 권한을 대신하지 않는다.

## 소스와 배포

통합 저장소의 `app-target.json`은 `{"site":"all"}`이다. 화면 원본은 `app-template.html`이며 전용 `index.html`을 생성한다.

```text
npm ci
npm run build:sites
npm test
git add .
git commit
git push
```

`index.html`을 직접 수정하면 다시 생성할 때 덮어쓴다. 화면 원본과 관련 JS/CSS를 수정한 후 생성한다. 자동 검사는 생성 결과의 최신 여부, 두 메뉴 전환, 로그인 복귀, 입력·경계 편집 중 전환 취소, 추후 기능 제외를 확인한다. 북측 자체 도면 추가는 북측용 drawing ID·API 범위·UI를 구성하는 별도 작업이다.

## 현재 GitHub 로그인

현재 GitHub 운영에서는 기존 Google OAuth 허용 반환 주소인 `https://deugyi.github.io/kds-check/`를 유지한다. 로그인 직전 통합 앱 식별자와 선택 현장을 sessionStorage에 저장하고, SDK의 PKCE 코드 교환 및 사용자 확인 후 통합 주소의 해당 현장으로 복귀한다. 복귀 정보는 15분간 유효하고 한 번만 사용한다. 외부 임의 URL은 받지 않는다.

이는 GitHub 운영 구성이다. 사내 다른 도메인으로 이전할 경우 해당 환경의 DB·인증 정책과 새 도메인에 맞게 별도 구성해야 한다. 사내 배포나 회사 SSO를 구현한 결과가 아니다.

복구는 통합 저장소의 변경 커밋을 revert하여 재배포한다. 기존 남측·북측 소스는 이전 버전 확인용으로 남겨둔다.
